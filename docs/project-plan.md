# 工程实践项目计划

以下为按阶段组织的初始计划，不预设课程截止日期或团队成员分工。

| 阶段 | 工作内容 | 交付物 | 状态 |
| --- | --- | --- | --- |
| 1. 项目初始化 | 明确问题、需求、架构与目录结构 | Git 仓库、README、设计文档 | 已完成 |
| 2. 模型与版本 | 选择公开示例数据，训练与评估模型，登记两个版本 | 可复现训练脚本、模型元信息 | 待开始 |
| 3. 服务与部署 | 完成预测、健康检查、版本查询及容器化 | 推理服务、部署说明 | 待开始 |
| 4. 监控与告警 | 采集运行指标，配置面板与阈值规则 | 监控配置、面板与基线结果 | 待开始 |
| 5. 回滚闭环 | 实现人工及自动回滚，加入并发与冷却保护 | 回滚控制器、操作事件记录 | 待开始 |
| 6. 测试与答辩 | 故障注入、结果对比、文档完善与演示 | 测试报告、实验结果、答辩材料 | 待开始 |

## 代码与提交约定

- `main` 保持可供老师查看的项目状态；功能开发使用独立分支。
- 提交信息描述实际完成的内容，不把计划中的功能写成已实现。
- 每个阶段更新 README 中的进度与可复现说明。
- 核心行为具备针对性验证；依赖版本在形成可运行服务时锁定。

## 建议的验证场景

| 场景 | 预期结果 |
| --- | --- |
| 正常发布 | 新模型通过检查，服务版本更新，记录发布事件 |
| 新模型加载失败 | 发布失败，原服务继续可用 |
| 持续服务错误 | 规则满足后回滚稳定版本，并验证恢复 |
| 短时请求抖动 | 记录异常但不满足持续条件，不回滚 |
| 请求样本不足 | 标记证据不足，不触发自动回滚 |
| 监控指标缺失 | 标记监控异常，不误判为模型健康或效果下降 |
| 多条告警同时触发 | 同一次异常只执行一次版本切换 |
| 回滚目标无效 | 拒绝切换并生成明确事件 |
| 回滚后验证失败 | 停止自动循环切换，进入人工处理状态 |

## 答辩材料规划

- 项目背景与需求分析。
- 系统架构、模块划分及回滚状态转换。
- 可复现的部署与演示流程。
- 故障注入方式、检测耗时、回滚耗时及恢复结果。
- 已实现范围、实际限制与后续改进方向。
